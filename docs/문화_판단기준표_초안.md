# 한국-미국 업무 메시지 문화적 해석 차이 판단기준 표 (초안)

## 설계 원칙
- **출처**: Erin Meyer *The Culture Map* 8개 축 중 업무 텍스트 메시지와 직결되는 4개 축(Scheduling, Evaluating, Disagreeing, Communicating) 활용
- **분류 방식**: KoBBQ 논문의 3단계 문화 적응 프레임워크 적용
  - `양방향 공통`: 어느 방향이든 동일하게 모호함 (Simply-Transferred에 대응)
  - `방향별 상이`: 발신/수신 방향에 따라 다른 패턴으로 나타남 (Target-Modified에 대응)
- **검증 필요**: 아래 항목은 프레임워크 기반 초안이며, 한-미 협업 경험자 3~5명 인터뷰로 실제 빈도·공감도를 검증해야 함 (☐ 표시 = 미검증)
- **주의**: 국적으로 단정하지 않기 위해 모든 항목은 "이렇게 해석될 수 있다"는 가능성으로 서술. "한국인은 항상 이렇게 말한다"는 단정적 서술 금지
- **전체 인용**: `docs/references.md`

## 1. Scheduling (시간 표현) — 양방향 공통

| ID | 원문 표현 예시 | 문제되는 이유 | 명시적 개선 표현 | 검증 |
|---|---|---|---|---|
| T01 | "내일까지 부탁드려요" | 발신자/수신자 시간대 기준 불명확 | "7월 30일 오후 6시 KST까지" | ☐ |
| T02 | "빠른 시일 내로" | 상대적 표현, 구체적 기한 없음 | "이번주 금요일 오후 5시까지" | ☐ |
| T03 | "가능하면 오늘 중으로" | '가능하면'이 우선순위를 낮추는지 실제 마감인지 모호 | "오늘 필수 마감 / 오늘이 이상적이나 늦어도 내일 정오까지 가능" 중 명시 | ☐ |
| T04 | "이번 주 중으로" | 요일 범위가 넓어 실제 작업 착수 시점 예측 어려움 | "수요일까지 초안, 금요일까지 최종본" | ☐ |
| T05 | "곧 다시 연락드릴게요" | '곧'의 기준(시간 단위)이 문화/개인마다 상이 | "2시간 내로 회신 / 내일 오전까지 회신" | ☐ |

## 2. Evaluating / Disagreeing (피드백·반대 표현) — 방향별 상이

| ID | 방향 | 원문 표현 예시 | 발신자 의도(고맥락/완곡 문화) | 수신자 해석(저맥락/직접 문화) | 명시적 개선 표현 | 검증 |
|---|---|---|---|---|---|---|
| F01 | KR→US | "이 방향도 좋은데 조금 더 고민해보면 어떨까요" | 현재 안 재검토 요청 (완곡한 반대) | 긍정 평가 + 선택적 제안 | "현재 방향 재검토를 요청합니다. 대안을 포함한 수정안을 부탁드려요" | ☐ |
| F02 | KR→US | "다들 그렇게 생각하시는 것 같아요" | 팀 차원의 우려 전달 | 근거 없는 동조 압박 | "○○, □□ 두 분도 동일한 우려를 표하셨습니다 (구체적 근거)" | ☐ |
| F03 | KR→US | "괜찮은 것 같아요, 근데..." | '근데' 이후가 핵심 피드백 | '괜찮다'는 승인으로 읽고 이후 내용 경시 | 승인 여부와 수정 요청을 별도 문장으로 분리 | ☐ |
| F04 | US→KR | "This is great, but I think we should reconsider X" | 구체적 수정 필요 (직접 피드백) | 전체 승인 후 사소한 코멘트로 축소 해석 | 승인 상태와 필수 수정사항을 구분해 명시 | ☐ |
| F05 | US→KR | "I strongly disagree with this approach" | 업무적 반대, 개인적 감정 아님 | 강한 어조로 인해 관계 악화 신호로 오해 | 반대 근거 + 대안을 함께 제시하도록 구조화 | ☐ |
| F06 | US→KR | "Can you walk me through your reasoning?" | 의사결정 근거에 대한 실질적 의문 | 결정에 대한 불신/추궁으로 오해 | 목적(이해를 위한 질문임을 명시)과 질문 분리 | ☐ |

## 3. Deciding (결정 상태 모호성) — 양방향 공통

| ID | 원문 표현 예시 | 문제되는 이유 | 명시적 개선 표현 | 검증 |
|---|---|---|---|---|
| D01 | "일단 이렇게 진행해봐요" | 최종 승인인지 임시 시도인지 불명확 | "이 안으로 최종 확정 / 1차 테스트로 진행, 결과 보고 결정" 중 명시 | ☐ |
| D02 | "Review complete" | 조직마다 '완료'의 의미가 다름 (최종 승인 vs 1차 검토) | 조직별 용어 사전 매핑 후 표준 상태값으로 표시 | ☐ |
| D03 | "확인했습니다" | 승인/단순 수신 확인 구분 안 됨 | "승인합니다" vs "확인했고, 검토 중입니다" 구분 | ☐ |
| D04 | "이견 없습니다" | 적극 동의 vs 소극적 무이의 구분 안 됨 | "동의합니다" vs "특별한 의견 없어 진행에 동의합니다" 구분 | ☐ |
| D05 | "나중에 다시 얘기해요" | 결정 보류인지 거절의 완곡 표현인지 모호 | 보류 사유 + 재논의 예정 시점 명시 | ☐ |

## 4. Communicating (고맥락/저맥락 일반) — 방향별 상이

| ID | 방향 | 원문 표현 예시 | 문제되는 이유 | 명시적 개선 표현 | 검증 |
|---|---|---|---|---|---|
| C01 | KR→US | 맥락 설명 없이 결론만 전달 | 저맥락 문화권은 배경 설명 부재 시 결정 근거 부족하다고 느낌 | 결론 + 핵심 근거 1~2줄 추가 | ☐ |
| C02 | US→KR | 배경 설명 없이 직접적 지시 | 위계/관계 맥락 생략 시 일방적 지시로 느껴질 수 있음 | 지시 목적과 배경을 간단히 포함 | ☐ |
| C03 | 양방향 | 이모지/느낌표 사용 빈도 차이 | 친근함의 신호 vs 진지함 부족 신호로 상반되게 해석 | 팀 내 톤 가이드라인으로 별도 합의 | ☐ |
| C04 | 양방향 | 침묵(응답 없음) | 이의 없음의 신호 vs 미확인 상태로 상반되게 해석 | 일정 시간 내 무응답 시 처리 규칙을 사전 합의 | ☐ |
